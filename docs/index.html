// 02 · one step

How a step works

Every step is the same five moves. The only network call is one typed decision; there is no prompt, no generated text, and nothing the model says ever becomes a selector or a script.

Observe

one Runtime.evaluate runs snapshot.js: visible text, every control as [e12] button "Search", identity guards

1 CDP call

Decide

one Jev request with five typed questions: operation, target, which value, did the last step work, is the goal done

~300 ms

Act

guard re-checked, geometry re-resolved, hit-tested, then a trusted Input.dispatchMouseEvent / insertText

trusted input

Verify

url, title, text and field values diffed before vs after; loop detection on three unchanged pages

deterministic

Done or hand back

DONE needs goal_achieved ≥ 0.6 in the same answer; otherwise escalate with a reason and the top candidates

// 03 · anatomy of a decision

Five questions, one request, no text.

Jev is a decision model, not a chat model. jev-ra sends the page as state and asks typed questions; it gets back a choice with a probability distribution and yes/no answers with confidence. That is why a step costs about $0.00025 and never has to parse prose.

request · state + questionsPOST /decisions

operation choice CLICK · TYPE_TEXT · SELECT · SCROLL_DOWN · SCROLL_UP · WAIT · DONE · BLOCKED
click_target choice [e3] link "신상품순" · [e4] link "판매순" · [e9] button "장바구니" · …
value_for_field choice origin: "Zurich" · destination: "London" · none
prev_ok noul Did the previous action have its intended effect on this page?
goal_achieved noul Is every requirement of the goal visibly satisfied on this page?
state: { page: {url, title, text ≤ 6000 chars}, elements[≤ 250], recent_actions[≤ 10], goal, values_available }

answers · 312 mstypesafe/jev-1.13

operation → CLICK p=0.91
click_target → [e3] link "신상품순" p=0.87
value_for_field → none
prev_ok → true 0.94
goal_achieved → false 0.12
→ act: click e3 (guard ok, hit-test ok) · verify: text changed, page_changed=true · next step

Question ids and instruction texts are the ones in jev_ra/decide/questions.py; the model answers are illustrative. Values your agent passes are only ever chosen by name; jev-ra never invents a string to type.

// 04 · architecture

Three processes, two wires, one decision model.

Your agent talks MCP over stdio. jev-ra owns a real Chrome through the DevTools Protocol and asks Jev for every step. Nothing else runs.

Why no screenshotsThe snapshot is text and an element table, so a step sends a few KB and Jev answers in ~300 ms. Screenshots are available as a tool for the rare case text is not enough.
Why the model never touches the DOMEvery target is an observed node id. Before input, jev-ra re-checks the element's identity guard and hit-tests its geometry; a covered or changed control raises stale instead of clicking the wrong thing.
Why your agent stays in chargejev-ra does not plan, does not invent text, and does not summarise. It executes a concrete goal fast and hands the page back with candidates the moment it cannot.
Python 3.12+ uv · uvx jev-ra Node launcher · npx jev-ra MCP · stdio Chrome DevTools Protocol TypeSafe Jev · jev-1.13 OpenRouter

// 05 · escalation contract

When it cannot, it says why.

Eight reasons, each with a prescribed move for the agent. The reply always carries the top candidates and the page text, so the agent can act without another observe.

needs_valuea field needs a string you did not supply. Add it to values, call again.
stuck_loopthree steps, no page change. Read the text, click one candidate, continue.
unverified_doneJev says done, no visible proof. Check with browser_extract.
stalethe page kept changing under it. browser_wait(), retry once.
budgetsteps or time ran out. Narrow or split the goal.
too_many_controlsover 250 controls in view. Scroll or open the section first.
blockedlogin, captcha, empty results. Tell the user; do not retry blindly.
invalid_decisionan answer not on the page, twice. Re-observe and drive one step yourself.

// 07 · install

One line.

Works with the OpenRouter key you already have; no TypeSafe account required. jev-ra doctor proves the whole path with one live decision.

export OPENROUTER_API_KEY=sk-or-...
uvx jev-ra install claude
uvx jev-ra doctor
# then in Claude Code: "search the web for X and summarise"
export OPENROUTER_API_KEY=sk-or-...
uvx jev-ra install codex
uvx jev-ra doctor
# Codex asks you to trust the new MCP server once
export OPENROUTER_API_KEY=sk-or-...
npx -y jev-ra install claude   # or: install codex

// 08 · limits

What it will not do (yet)

These escalate to your agent with a reason instead of guessing.

Out of scope in v0.1

  • Cross-origin iframes (same-origin and open shadow roots work)
  • Canvas-drawn UIs
  • File uploads
  • Captchas, bot walls
  • Multi-tab workflows

By design

  • Never types a value your agent did not supply (no guessed personal data)
  • Never turns model output into selectors or JavaScript
  • Never reports done without a visible check
  • Sends visible page text to Jev; never file bodies or screenshots
